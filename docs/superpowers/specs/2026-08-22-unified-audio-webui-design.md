# FireRedAudio Studio 统一 WebUI 设计

日期：2026-08-22  
状态：待用户最终审阅  
目标：将 mlx-FireRedAudio 的理解、生成和编辑能力统一为面向普通用户、专业创作者与开发者的本地 WebUI。

## 1. 产品定位

FireRedAudio Studio 是本地优先的 AI 音频工作流中心。它同时提供快捷工具和项目工作台：用户可以立即完成一次转写、配音或编辑，也可以把素材、声音模板、任务和结果沉淀为长期项目。

首版服务对象包括内容创作者、会议与录音用户、语音工具开发者。首版只监听本机地址，不包含账号、支付、云同步、多人协作或远程部署。

## 2. 首版范围

首版必须覆盖：

1. ASR 单音频与多音频转写。
2. Audio QA，可选思考模式。
3. Zero-shot TTS 与声音模板保存。
4. 语义编辑。
5. 声学编辑：速度、音高、音量。
6. Voice Design。
7. 项目、素材、声音和结果管理。
8. 单模型实例与持久化任务队列。
9. 本地 API，供 WebUI 和第三方客户端共用。
10. 音频播放、基础波形、结果下载与任务重试。

首版不实现轨道式非线性音频编辑器、实时流式推理、运行中任务强制中断、用户系统、插件市场和计费。

## 3. 技术方案

采用 FastAPI + React/Vite：

- Python/FastAPI 负责项目数据、文件访问、任务队列和 MLX 推理。
- React/Vite 负责工作台、表单、波形、播放器、状态更新和错误展示。
- WebUI 与外部客户端使用同一组版本化 REST API。
- Server-Sent Events 推送模型状态、任务状态和阶段进度；不为首版引入双向 WebSocket。
- 单个常驻 `FireRedAudioInference` 实例服务所有任务。
- 单条 GPU 工作队列串行执行推理，避免并发模型副本和统一内存争用。

## 4. 系统边界

后端划分为以下独立组件：

- `ModelManager`：加载并持有唯一模型实例，报告设备、内存和就绪状态。
- `JobQueue`：持久化排队任务，保证一次只运行一个 MLX 任务。
- `InferenceService`：把六类任务参数转换为现有推理 API 调用并验证结果。
- `ProjectStore`：读写项目、素材、声音、任务和结果元数据。
- `AudioService`：输入检查、元数据读取、波形摘要、预览和安全文件导出。
- `API`：提供项目、素材、声音、任务、模型状态和事件流接口。
- `WebUI`：只通过 API 访问数据，不直接依赖模型模块或本地文件结构。

组件之间使用显式数据模型，不共享可变全局状态；模型实例仅由 `ModelManager` 持有。

## 5. 页面结构

固定侧栏包含：

- 首页
- 项目
- 快捷工具
  - 转写问答
  - 声音克隆
  - 语音编辑
  - 音色设计
- 素材库
- 声音库
- 任务中心
- 设置

顶部状态栏持续显示模型状态、当前任务、等待数量和本机内存提示。

### 5.1 首页

显示四个快捷工具、最近项目、最近生成结果及模型状态。首次使用时引导用户选择模型目录和输出目录。

### 5.2 项目工作台

左侧显示项目素材，中间显示播放器和基础波形，右侧为当前工具参数与结果。素材可以直接发送到转写问答、声音克隆或语音编辑。快捷工具结果可一键保存为现有项目或新项目。

### 5.3 快捷工具

- 转写问答支持一个或多个音频、问题、思考模式和输出保存。
- 声音克隆要求参考音频、准确参考文本、目标文本和语言。
- 语音编辑先选择语义或声学模式；声学模式通过控件生成模型支持的标准英文指令。
- 音色设计接受自然语言音色描述和目标文本，并展示结构化音色结果。

### 5.4 任务中心

显示任务类型、项目、状态、阶段、排队顺序、耗时、结果和错误。允许取消等待任务、重试失败或中断任务、打开结果所在项目。

## 6. 视觉与交互

采用深色专业音频工作室风格，重点突出音频、任务状态和主要操作。普通用户默认只看到快速、平衡、高质量三个档位：

- 快速：Flow 4 步、ASR 单束解码，适合预览。
- 平衡：Flow 4 步、ASR 四束解码，采用已审计的 M3 Max 平衡配置并作为默认档。
- 高质量：Flow 10 步、ASR 四束解码，保持模型质量默认值。

ASR 默认使用四束搜索。高级区域允许调整最大文本长度、最大音频步数、CFG、随机种子和输出路径。危险或难以解释的参数不在普通模式展示。

界面在桌面宽度优先设计，最低支持 1280 像素；首版不承诺移动端完整编辑体验。

## 7. 本地数据模型

默认数据根目录为 `workspace/`：

```text
workspace/
├── projects/<project-id>/
│   ├── project.json
│   ├── inputs/
│   ├── outputs/
│   └── transcripts/
├── voices/<voice-id>/
│   ├── reference.wav
│   └── voice.json
├── jobs/<job-id>.json
└── settings.json
```

核心对象：

- Project：标识、名称、创建与更新时间、素材和任务引用。
- Asset：标识、文件路径、类型、来源、时长、采样率、声道和项目引用。
- Voice：标识、名称、参考素材、准确文本、语言和备注。
- Job：标识、任务类型、参数、状态、阶段、时间、结果引用和错误。
- Result：文本、推理内容、生成音频、潜变量元数据和性能数据。

元数据采用 JSON 原子写入。媒体文件不嵌入 JSON。所有项目内路径保存为相对数据根目录的路径，避免移动工作区后失效。

## 8. 任务生命周期

任务状态为：

```text
queued -> loading -> preprocessing -> inferencing -> exporting -> completed
                                                      \-> failed
queued ------------------------------------------------> cancelled
服务异常退出 -------------------------------------------> interrupted
```

规则：

- 只有 `queued` 任务可以取消。
- 运行中任务首版不强制中断。
- 服务启动时把遗留的运行状态转换为 `interrupted`。
- `failed` 和 `interrupted` 任务可以复制原参数重新排队。
- 结果先写临时文件，验证成功后原子移动到正式目录。
- 页面刷新或浏览器关闭不影响后台任务。

## 9. API 设计

API 使用 `/api/v1` 前缀，至少包括：

- `GET /model/status`
- `GET /events`
- `GET|POST /projects`
- `GET|PATCH|DELETE /projects/{id}`
- `GET|POST /assets`
- `GET|POST /voices`
- `GET|POST /jobs`
- `GET /jobs/{id}`
- `POST /jobs/{id}/cancel`
- `POST /jobs/{id}/retry`
- `GET /results/{id}`
- `GET /media/{asset_id}`，支持音频范围请求

上传、路径和参数必须在进入队列前验证。删除项目或素材属于破坏性操作，必须由界面二次确认；被任务或声音模板引用的素材不得直接删除。

## 10. 输入和结果验证

提交前检查：

- 文件存在且可读取。
- 音频格式、时长、声道和采样率可解析。
- TTS 参考文本非空且长度合理。
- 语义与声学编辑指令符合对应模式。
- 输出目录可写。
- 参数位于模型支持范围内。

任务完成前检查：

- ASR 和 QA 结果不能是空文本。
- 生成音频必须非空、有限且不为全静音。
- 语义编辑必须返回改写文本。
- 输出文件必须可重新读取且采样率为预期值。

验证失败时任务进入 `failed`，不得显示成功。

## 11. 错误处理

- 内存不足：停止接收新的推理任务，尝试清理 MLX 缓存，并提示关闭其他模型或降低任务规模。
- 模型加载失败：保留项目管理能力，禁用推理提交并显示可操作错误。
- 输入异常：不进入队列，直接定位到具体字段。
- 推理异常：记录技术日志，界面显示简短中文原因和重试入口。
- 导出失败：保留临时结果并允许重新导出。
- 服务重启：恢复项目和历史任务，不自动重跑中断任务。

API 错误统一包含 `code`、`message`、`details` 和 `request_id`；日志不得记录完整用户音频、敏感文本或绝对路径之外的额外隐私数据。

## 12. 安全与本地隐私

- 默认绑定 `127.0.0.1`，不绑定局域网或公网地址。
- 媒体接口只允许访问数据根目录内登记过的文件。
- 文件名不直接作为磁盘路径，使用服务生成的标识。
- 上传大小和音频时长有明确限制。
- 不执行用户提供的命令、模板代码或任意文件路径。
- 设置页明确说明本地处理边界以及用户主动导出的位置。

## 13. 测试与验收

自动测试：

- 数据模型和原子写入测试。
- 项目、素材、声音和任务 API 测试。
- 单模型实例和单消费者队列测试。
- 状态恢复、取消、重试和错误映射测试。
- React 关键页面、表单和状态展示测试。
- 波形摘要和范围请求测试。
- 空文本、静音、非有限音频及语义编辑缺文本的失败测试。

真实模型验收：

- 六条能力各完成一次真实 MLX 冒烟测试。
- 连续执行至少十个混合任务，确认不会创建第二个模型实例。
- 记录每个任务的延迟、音频时长和峰值内存。
- 服务退出后不存在残留推理子进程。

## 14. 交付阶段

第一阶段交付基础设施：FastAPI、React 壳、设置、模型状态、项目存储和任务队列。

第二阶段交付四个快捷工具和六条推理路径，包括输入与结果验证。

第三阶段交付项目工作台、素材库、声音库、波形、任务中心和跨工具流转。

第四阶段完成真实模型回归、连续任务内存测试、打包说明和本地启动体验。

每一阶段结束时系统均应可启动、可测试，不依赖后续阶段才能恢复基本运行。

## 15. 成功标准

首版完成需同时满足：

1. 普通用户无需命令行即可完成六类任务。
2. 快捷任务可以保存到项目，项目素材可以发送到任意兼容工具。
3. 同一服务生命周期内只存在一个 FireRedAudio 模型实例。
4. 任务历史在刷新和重启后仍可查看。
5. 错误结果不会被标记为成功。
6. API 与 WebUI 共享相同任务逻辑。
7. 六条真实 MLX 冒烟测试和十任务连续稳定性测试通过。
8. 默认仅本机可访问，项目外文件不能通过媒体接口读取。
